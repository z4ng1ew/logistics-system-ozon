## 1. Постановка задачи и исходные данные

Требуется концепция сортировочного центра (СЦ) с максимально возможным уровнем
автоматизации и его имитационная модель — цифровое представление процессов,
позволяющее проверить работоспособность схемы, найти узкие места и обосновать
потребность в площади, людях и оборудовании.

Исходные данные (все — из официальной постановки):

| Параметр | Значение |
|---|---|
| Входящий поток | 100 000 товаров/час |
| Тара | КТЯ (картонный тарный ящик) 600×400×400 мм, в среднем 27 товаров |
| Поток КТЯ / палет | ≈3 700 КТЯ/час; палета 800×1200 по 20 КТЯ → 185 палет/час |
| Направления сортировки | 400; на 20 % направлений — до 80 % объёма |
| Ограничение товара | сторона упаковки ≤ 320 мм, иначе nonsort |
| Автосортировщик | 10 000 товаров/час; при ручной загрузке ≥ 1 000 тов/ч на оператора |
| Ручная сортировка | 250 товаров/час/чел по 20 направлениям (800 чел на 400 направлений) |
| Контур тары | 80 % КТЯ — повторное использование, 20 % — брак, возмещается новыми |
| Отгрузка | 24 ворот; машина = 16 палет КТЯ + 16 роллкейджей nonsort; погрузка 2 ч |
| Исходящий поток | = входящему: 100 000 тов/час в КТЯ, одна коробка — одно направление |

Доля nonsort-потока в постановке не задана — принята параметром модели
(базовое значение 5 %, изменяется без правки кода).

## 2. Выбранный подход

Работа построена в два слоя, как того требует постановка:

1. **Аналитическая модель** (раздел 3) — балансовые расчёты потоков и мощностей
   на средних значениях. Она определила состав оборудования и предсказала
   узкие места.
2. **Имитационная модель** (разделы 5–6) — полноценная дискретно-событийная
   симуляция (события — прибытия, обработки, освобождения ресурсов —
   разыгрываются во времени) на SimPy. Она проверила предсказания аналитики
   в динамике: очереди, переходные процессы, каскадные эффекты, сценарии.

Такой порядок делает каждую цифру проверяемой: сначала формула, потом
подтверждение симуляцией.

## 3. Аналитическая модель (ключевые результаты)

Полный текст — `docs/analytical_model.md`. Главное:

**3.1. Сквозные потоки согласованы.** 100 000 ÷ 27 = 3 703,7 КТЯ/ч;
÷ 20 = 185,2 палет/ч — сходится с 185 палет/ч из постановки.

**3.2. Ворота отгрузки — узкое место «по построению».** Потребность
185 ÷ 16 = 11,57 машин/ч при мощности 24 ÷ 2 ч = 12,00 машин/ч.
Утилизация 96,4 % — резерва почти нет; буфер отгрузки обязателен,
сбой на воротах каскадно останавливает потоки выше.

**3.3. Сортеров нужно 11, а не 10.** 100 000 ÷ 10 000 = 10 единиц — это
загрузка ровно 100 % без права на пики и ретраи. Базовая схема: 11 единиц,
расчётная загрузка ~91 %.

**3.4. Тяжёлые направления требуют дробления (мульти-скат).** При весах
Ципфа (степенное распределение: вес направления убывает по закону 1/номер^s;
показатель s подобран численно под правило «20 % направлений = 80 % объёма»)
топ-направление несёт ≈18 575 тов/ч — больше мощности целого сортера.
Жёсткая привязка «направление → один сортер» физически нереализуема.
Решение: выходные скаты тяжёлого направления размещаются на нескольких
сортерах; балансировка кусками ≤ 1/N потока (эвристика LPT — «самый тяжёлый
кусок в наименее загруженный сортер») даёт разброс загрузки сортеров 0,09 %.

**3.5. Мощности участков** (расчёт → принято → загрузка):
депаллетизация 7 роботов (88 %), вскрытие КТЯ 16 станций (96 %),
инфид 14 автостанций (89 %), сортеры 11 (91 %), заклейка 12 (86 %),
палетизация 9 роботов (91 %), ворота 24 (96 %), ручной разбор nonsort
22 места (91 % при доле 5 %).

**3.6. Люди.** Ручная схема из постановки — 800 чел/смена. Автоматическая
загрузка сортеров снимает ограничение 1 000 тов/ч на оператора; людей на
основных операциях не остаётся. Штат смены — порядка 30–35 человек
(разбор nonsort, контроль исключений, наладка, диспетчер): сокращение ≈96 %.

## 4. Концепция центра

### 4.1. Схема потока

Сквозной поток без встречных перемещений (см. `docs/layout_scheme.svg`):
приёмка (8 доков) → буфер 80 палет → депаллетизация (7 роботов, снятие
стрейча и ленты) → конвейер → вскрытие КТЯ (16) → инфид (14 автостанций,
сканирование, отделение nonsort) → 11 сортеров → 400 скатов-направлений
(закрытие КТЯ по наполнению 27 шт или таймауту 45 мин) → заклейка (12) →
сортировка КТЯ по воротам → палетизация (9 роботов) → гравитационный буфер
отгрузки → 24 ворот. Параллельно: контур тары (80 % реюз с подачей пустых
КТЯ с мезонина самотёком, 20 % брак → пресс, машина новых коробов) и
nonsort-контур (ручной разбор 22 места → роллкейджи → те же машины).

### 4.2. Уровень автоматизации по операциям

| Операция | Как выполняется | Роль человека |
|---|---|---|
| Разгрузка машин | погрузчики/AGV (автоматические тележки) | операторы техники |
| Депаллетизация | роботы-депаллетизаторы | 0 (контроль удалённо) |
| Транспортировка КТЯ | конвейерный контур | 0 |
| Вскрытие КТЯ | автоматические станции | точечный контроль |
| Загрузка сортеров (инфид) | автоматическая — снимает лимит 1 000 тов/ч/чел | 0 |
| Сортировка на 400 направлений | 11 автосортеров, мульти-скат | 2–3 оператора контроля |
| Контроль заполнения, съём | автоматика скатов + таймаут | точечный контроль |
| Заклейка | автоматические заклейщики | 0 |
| Палетизация | роботы + обмотчики | 0 |
| Погрузка машин | телескопические конвейеры/погрузчики | операторы техники |
| Nonsort-поток | ручной разбор по адресным ячейкам | 22 человека — главный ручной участок |

Итог: человек остаётся там, где автоматизация пока нерентабельна
(nonsort, стыки с транспортом, контроль исключений).

### 4.3. Площадь и компоновка

Полный расчёт — `docs/layout.md`. Полезные площади посчитаны снизу вверх
от числа оборудования: ≈9 500 м²; коэффициент компоновки 2,0 (проезды,
противопожарные разрывы, нестыковки сетки). Ширину здания диктует ряд
сортеров (11 × 12 м = 132 м → 140 м), глубину — сумма технологических
полос (135 м). Итог: **здание 140 × 135 м ≈ 18 900 м²** с мезонином
(тара, АБК, техпомещения на отметке +6 м) — ниже нижней границы ориентира
20 000–24 000 м² без ужимания проездов. Консервативный одноуровневый
вариант — 20 600 м².

## 5. Имитационная модель

### 5.1. Инструменты

| Слой | Инструмент | Обоснование |
|---|---|---|
| Ядро симуляции | SimPy (Python 3.12) | из перечня рекомендованного open-source ПО; прозрачная логика |
| Расчёты | NumPy | веса Ципфа, розыгрыш направлений, биномиальный nonsort |
| Метрики | CSV/JSON, стандартная библиотека | нейтральные форматы из требований |
| Дашборд | Streamlit + Plotly | графики + смена параметров без правки кода |
| Воспроизводимость | Docker, Makefile, фиксированный seed | идентичный запуск в среде проверки |

### 5.2. Устройство модели

Единица потока — КТЯ; товары учитываются счётчиками внутри КТЯ (допущение
A-01: поштучные события не меняют системные метрики, но замедляют прогон
в ~30 раз). Сутки модельного времени считаются за ~30 секунд.

Каждая операция пишет счётчики в минутные бакеты; агрегаты строятся окнами
**1 мин / 1 ч / 12 ч / 24 ч** (требование к метрикам). Очереди замеряются
каждые 30 с; загрузка ресурсов — по занятому времени. В конце прогона
выполняется балансовая сверка: вход = сортировка + nonsort + очереди.

Все 16+ операций постановки отражены: приёмка палет, депаллетизация,
транспортировка, вскрытие КТЯ, инфид, отделение nonsort, автосортировка,
наполнение и закрытие выходных КТЯ (по 27 шт или таймауту), контур тары
(реюз/брак/новые), заклейка, транспортировка к отгрузке, сортировка КТЯ
по направлениям, палетизация, ворота (машина = 16 палет + 16 роллкейджей,
погрузка 2 ч), ручной разбор nonsort, формирование роллкейджей.

Реестр допущений с обоснованиями и путями снятия — `docs/assumptions.md`.

### 5.3. Изменяемые параметры

Любой параметр меняется из командной строки или дашборда без правки кода:
интенсивность потока, число сортеров, режим назначения направлений
(split/strict), режим инфида (auto/manual), доля nonsort, число станций
каждого участка, таймаут скатов, горизонт, зерно случайности.

Пример: `python -m src.run --set sorters.count=10 --set flow.p_nonsort=0.08`

### 6.2. Переходный процесс и волновая отгрузка

На окне 1 час виден переходный период (~2,5 ч): конвейер наполняется,
первые машины уезжают только после первой 2-часовой погрузки. Далее график
отгрузки — затухающая «пила»: партии машин уходят волнами, очередь палет
у ворот колеблется с убывающими пиками (330 → 300 → 270 → ...) и к концу
суток входит в устойчивый ритм. Система самостабилизируется — признак
корректно сбалансированной схемы.

[РИС. 4: скриншот — очередь pallets_awaiting_gates, затухающая пила]

### 6.3. Сценарное сравнение: цена архитектурных решений

| Показатель | База: 11 сортеров, split | 10 сортеров, split | 11 сортеров, strict |
|---|---|---|---|
| Отсортировано | 2 270 963 | 2 271 249 | 2 088 988 |
| Отгружено | 2 064 038 | 2 064 443 | 1 891 428 |
| Застряло в очередях | **117** | **148** | **182 017** |
| Загрузка сортеров | 83 % | 95 % | средняя низкая, локальный перекос |

Выводы:

1. **strict (без дробления направлений) теряет 7,6 % потока за сутки** —
   182 тыс. товаров копятся в очереди сортера, обслуживающего топ-направление
   (18,6 тыс. тов/ч на входе против 10 тыс. мощности). Симуляция численно
   подтвердила аналитический вывод §3.4 о необходимости мульти-ската.
2. Важная методическая деталь: средняя загрузка сортеров в strict выглядит
   безобидно, потому что перегружены 1–2 машины из 11 — **среднее маскирует
   локальный перекос, правду показывает динамика очереди**. Поэтому модель
   отслеживает и утилизацию, и очереди.
3. 10 сортеров работают на пределе (95 %) без запаса на пики и отказы;
   11-й сортер — страховой резерв за счёт ~9 % запаса мощности.

[РИС. 5: скриншот — рост очереди сортеров в data/out_strict против ровной в базе]

### 6.4. Чувствительность к доле nonsort

При базовых 5 % ручной разбор загружен на 90 % — участок на границе.
Рост доли крупногабарита/нечитаемых кодов выше ~5,5 % делает ручной разбор
новым узким местом: требуется +2 места на каждый дополнительный процент
(250 тов/ч на человека). Доля nonsort — самый дешёвый рычаг разгрузки
центра на стороне поставщиков (качество упаковки и штрихкодов).

### 6.5. Сводка проблемных зон

| Зона | Загрузка | Риск | Рекомендация |
|---|---|---|---|
| Ворота отгрузки | 96 % расчётно | каскадная остановка вверх по потоку | гравитационный буфер; сокращение времени погрузки |
| Вскрытие КТЯ | 96 % | первая очередь при пиках | +1–2 станции либо ускорение цикла до 13 с |
| Ручной разбор nonsort | 90 % | чувствителен к доле nonsort | резервные места; работа с качеством упаковки |
| Сортер топ-направления | перегрузка в strict | потеря 7,6 % потока | мульти-скат (реализован в базовой схеме) |

## 8. Ограничения и направления развития

Ключевые допущения (полный реестр — `docs/assumptions.md`): моделирование
на уровне КТЯ (A-01); ровно 27 товаров в КТЯ (A-02); доля nonsort —
параметр (A-03); времена операций — инженерные оценки, вынесены в конфиг
для калибровки (A-08); роллкейджи не задерживают отправку машины (A-06);
отказы оборудования — отдельный сценарий (A-10).

Развитие: калибровка времён операций по данным реальных объектов;
совместное ожидание палет и роллкейджей на воротах; сценарии отказов
(MTBF/MTTR — среднее время между поломками и время ремонта); оптимизация
балансировки через Google OR-Tools; 3D-визуализация потока; волновое
расписание отгрузки, синхронизированное с магистральным транспортом.

## 9. Выводы

1. Построена связная пара «аналитическая модель + имитационная модель»:
   каждая мощность выведена формулой и подтверждена динамикой симуляции.
2. Схема с 11 сортерами, автозагрузкой и мульти-скатом пропускает
   заявленные 100 000 тов/час: за сутки застревает 117 товаров из 2,39 млн.
3. Автоматизация сокращает персонал смены с 800 до ~30–35 человек (−96 %),
   сохраняя людей только на nonsort и контроле исключений.
4. Площадь 18 900 м² — ниже ориентира постановки, каждая цифра выводится
   из производительности участков; времена транспортировки в модели
   сверены с геометрией плана.
5. Модель выявляет проблемные зоны количественно: ворота (96 %), вскрытие
   (96 %), ручной разбор (90 %), и показывает цену отказа от дробления
   направлений — 7,6 % потока в сутки.
