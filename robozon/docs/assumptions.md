# Реестр допущений модели (v0.1)

Каждое допущение: что упрощено, почему это допустимо, как снять при необходимости.

| № | Допущение | Обоснование | Как снять (v0.2+) |
|---|---|---|---|
| A-01 | Единица моделирования — КТЯ; товары — счётчики внутри | 100 тыс. поштучных событий/час замедляют прогон в ~30 раз без выигрыша в точности системных метрик | Гибрид: поштучно на инфиде/сортере, агрегаты на транспорте |
| A-02 | В каждом входящем КТЯ ровно 27 товаров | В ТЗ задано среднее; дисперсия неизвестна | Распределение (напр., Пуассон вокруг 27) параметром |
| A-03 | Доля nonsort = 5% | В ТЗ не задана; является изменяемым параметром модели (критерий 5.2) | Сценарии 2–10%; уточнить у организаторов (T-12) |
| A-04 | Направление товара разыгрывается на инфиде по весам Ципфа (80/20) | ТЗ задаёт только агрегат «20% направлений — до 80% объёма» | Реальная матрица направлений, если дадут данные |
| A-05 | Дефицит пустой тары не блокирует закрытие КТЯ (берётся «новый» короб, поток считается) | Машина новых коробов (900/ч) покрывает потребность (741/ч) | Блокирующий Store тары + лимит машины |
| A-06 | Машина у ворот ждёт только 16 палет КТЯ; роллкейджи учитываются счётчиком и не задерживают отправку | Упрощение первого приближения | Совместное ожидание 16 палет + 16 роллкейджей |
| A-07 | Транспортировка = фиксированное время хода + ёмкость линии | Геометрия трасс появится вместе с компоновкой (T-07) | Скорость × длина маршрута из layout |
| A-08 | Времена операций (депал 120 с, вскрытие 15 с, заклейка 10 с, укладка 8 с/КТЯ, авто-инфид 0,45 с/тов) — инженерные оценки | В ТЗ не заданы; вынесены в конфиг и калибруются | Калибровка по публичным данным/консультации (T-02) |
| A-09 | Палета отгрузки собирается из любых 20 КТЯ (FIFO), направление палеты не контролируется | По ТЗ «на одной палете могут находиться КТЯ для нескольких направлений» | Группировка КТЯ по воротам/кластерам направлений |
| A-10 | Сбои оборудования не моделируются в базовом сценарии | Отдельный сценарий устойчивости | MTBF/MTTR параметры на ресурсы |

Все параметры допущений вынесены в `config.yaml` и меняются без правки кода
(критерий 5.2 «возможность менять параметры модели»).
