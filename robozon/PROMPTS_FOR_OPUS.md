# Промпты для параллельного окна Claude Opus

Правила использования:
1. Каждый промпт самодостаточен — Opus НЕ видит наш репозиторий, поэтому
   интерфейсы (схемы файлов) вшиты в текст. НЕ МЕНЯЙ схемы CSV/JSON в промптах,
   иначе куски не состыкуются с ядром.
2. Полученный код клади в указанный файл, прогоняй локально, коммить в feature-ветку.
3. Каждый член команды обязан понимать код, который сдаёт, — на защите
   оценивается «умение отвечать на вопросы» (критерий 1.2).

## P1 → `dashboard/app.py` (задача T-05, penroseg)

```
Напиши одностраничное Streamlit-приложение (файл dashboard/app.py) для
визуализации метрик имитационной модели сортировочного центра.

Входные данные лежат в папке, путь задаётся в сайдбаре (по умолчанию data/out):

1) operations_minutely.csv — колонки: minute (int), operation (str), count (float)
2) operations_agg.csv — колонки: window (str: 1min|1h|12h|24h), window_index (int),
   operation (str), count (float), rate_per_hour (float)
3) queues.csv — колонки: minute (int), queue (str), avg_length (float), max_length (float)
4) utilization.csv — колонки: resource (str), capacity (int),
   busy_resource_sec (float), utilization (float 0..1)
5) summary.json — ключи: horizon_sec, totals (dict операция->всего),
   utilization (dict ресурс->0..1), observations_avg (dict, там есть
   outbound_box_fill — средняя заполненность КТЯ), balance (dict:
   items_in, items_sorted, items_nonsort, items_shipped),
   operation_labels (dict: код операции -> русская подпись),
   config (полный YAML-конфиг прогона как dict)

Требования к интерфейсу (в таком порядке сверху вниз):
- Заголовок «Сортировочный центр — метрики» + карточки (st.metric):
  товаров вошло / отсортировано / отгружено / nonsort, из balance.
- Селектор окна агрегации (1min/1h/12h/24h) + мультиселект операций
  (подписи брать из operation_labels, по умолчанию 6 ключевых:
  infeed_items, sorted_items, sealing_boxes, palletizing_boxes,
  shipped_items, nonsort_items). График Plotly: rate_per_hour по времени.
- Раздел «Очереди»: line-график avg_length по minute для выбранных очередей.
- Раздел «Загрузка ресурсов»: горизонтальный bar-чарт utilization,
  подсветить >0.9 красным (это узкие места).
- Раздел «Запустить новый прогон»: number_input для sorters.count (8..14),
  flow.p_nonsort (0.0..0.15), selectbox infeed.mode (auto/manual),
  simulation.hours (2..24); кнопка запускает
  subprocess: python -m src.run --out data/out
  --set sorters.count=X --set flow.p_nonsort=Y --set infeed.mode=Z --hours H
  (рабочая директория — корень репо), показать stdout, затем st.rerun().
Стек: streamlit, plotly.express, pandas. Обработай отсутствие файлов
(подсказка «сначала выполните make run»). Код с русскими комментариями.
```

80% КТЯ переиспользуются, 20% брак возмещается новыми.

Ноутбук должен по шагам, с формулами в markdown и расчётом в коде:
1. Сквозные потоки: товары -> КТЯ/час -> палеты/час (сверить со 185 из ТЗ).
2. Ворота: машин/час требуется vs доступно, утилизация (ожидаю ~96%).
3. Сортеры: сколько нужно при 10000/час, что даёт 11-й (резерв).
4. Парето: веса Ципфа w_d ~ 1/d^s на 400 направлений, подбор s бинарным
   поиском под «top-20% = 80%». График весов (log-log). Вес топ-направления
   в товарах/час — показать, что он больше мощности одного сортера, вывод
   о необходимости дробления направления между сортерами.
5. Люди: 800 чел (ручная схема из ТЗ) vs автоматическая загрузка
   (снимает лимит 1000/час/чел) — таблица сравнения.
6. Контур тары: потребность в новых коробах/час.
7. Чувствительность: график «доля nonsort 0..15% -> нужное число
   работников ручной сортировки при 250 тов/час/чел».
Каждый раздел заканчивай выводом в 1-2 предложения. Библиотеки: numpy,
matplotlib. Без seaborn.

## P5 → `viz3d/` (задача T-06, браpenrosegт)

```
Напиши одностраничное three.js приложение (один index.html с CDN-подключением
three.js, без сборщиков) — упрощённая 3D-визуализация сортировочного центра.

Сцена (вид сверху-сбоку, OrbitControls): прямоугольный цех ~200x120 м.
Зоны (цветные плоскости + подпись спрайтом): буфер приёмки (слева),
7 роботов депаллетизации, конвейер (лента — вытянутые боксы), 16 станций
вскрытия, 14 станций инфида, 11 сортеров (крупные боксы в 2 ряда по центру),
скаты (мелкие боксы вдоль сортеров), 12 заклейщиков, буфер отгрузки,
9 палетайзеров, 24 дока-ворот (справа).

Анимация: коробки (маленькие кубы 0.6x0.4x0.4 в масштабе) спавнятся слева
каждые N мс (слайдер скорости), едут по маршруту приёмка -> депал ->
конвейер -> вскрытие -> инфид -> случайный сортер -> случайный скат ->
заклейка -> палетизация -> случайные ворота, исчезают у ворот. Часть
коробок (5%, слайдер) окрашивается красным (nonsort) и уходит на отдельную
зону ручной сортировки. Счётчики на экране: в пути / отгружено / nonsort.

Код должен уметь позже проигрывать реальный трейс из файла trace.json
формата: [{"t": секунды, "id": строка, "path": [[x,z], ...]}], но пока
работает в процедурном демо-режиме. Всё в одном файле, комментарии русские.
```
